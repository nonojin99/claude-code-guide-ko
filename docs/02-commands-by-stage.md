# 2. 작업 단계별 명령

명령은 외우기보다 **"지금 어느 단계인가"** 로 고르는 편이 쉽습니다.

## 작업을 시작할 때

| 명령 | 하는 일 | 이럴 때 |
|---|---|---|
| `/plan [할 일]` | 계획 모드로 들어가 먼저 계획을 세움 | 파일 여러 개를 고치는 큰 작업 |
| `/goal [조건]` | 조건을 만족할 때까지 여러 턴에 걸쳐 계속 작업 | "테스트가 모두 통과할 때까지" 같은 끝이 분명한 작업 |
| `/model` · `/effort` | 모델·추론 강도 변경 | 어려운 분석은 높게, 단순 반복은 낮게 |

`/goal` 은 인자 없이 쓰면 현재 목표를 보여주고, `/goal clear` 로 중간에 멈춥니다.

## 작업 중에

| 명령 | 하는 일 | 이럴 때 |
|---|---|---|
| `/btw [질문]` | 대화 기록에 남기지 않는 곁가지 질문 | 작업 흐름을 흐리지 않고 잠깐 물어볼 때 |
| `/context` | 대화 창을 무엇이 채우고 있는지 색깔 격자로 표시 | 답이 엉뚱해지기 시작할 때 |
| `/compact [초점]` | 지금까지 대화를 요약해 공간 확보 | 대화가 길어졌지만 이어서 해야 할 때 |
| `/tasks` | 백그라운드 작업 목록 보기 | 서브에이전트에 맡긴 일이 있을 때 |

## 결과를 넘기기 전에

| 명령 | 하는 일 |
|---|---|
| `/diff` | 지금까지 바뀐 내용(Claude가 고친 것 포함) 보기 |
| `/code-review` | 변경분의 정확성 버그 찾기. `--fix` 를 붙이면 바로 고침. `/review` 와 같음 |
| `/simplify` | 리뷰 에이전트 4개가 병렬로 군더더기를 찾아 정리(버그는 찾지 않음) |
| `/security-review` | 현재 브랜치 변경분의 보안 취약점 점검(git 원격 저장소 필요) |
| `/verify` | 앱을 실제로 빌드·실행해 변경이 동작하는지 확인 |

## 대화를 관리할 때

| 명령 | 하는 일 |
|---|---|
| `/clear` | 새 대화로 시작(프로젝트 설정은 유지). 다른 주제는 새 대화가 정답 |
| `/resume` | 이전 대화 이어가기 |
| `/branch` | 현재 대화를 갈래로 나눠 다른 방향 시도(원래 대화는 보존) |
| `/rewind` | 코드와 대화를 이전 체크포인트로 되돌리기. `/undo` 와 같음 |
| `/export` | 대화를 텍스트로 내보내기 |

## 문제가 생겼을 때

| 명령 | 하는 일 |
|---|---|
| `/doctor` | 설치·설정·`CLAUDE.md` 문제를 진단하고, 확인을 받은 뒤 고침 |
| `/debug` | 디버그 로그를 켜고 현재 세션 문제 추적 |
| `/feedback` | Anthropic에 문제 보고 |

## 익숙해진 뒤

| 명령 | 하는 일 |
|---|---|
| `/insights` | 최근 세션을 분석한 HTML 리포트: 주로 하는 일, 막히는 곳, 써볼 기능(로컬 PC에서만) |
| `/loop [간격] [프롬프트]` | 세션이 열려 있는 동안 반복 실행. 예: `/loop 5m 배포 끝났는지 확인` |
| `/schedule` | 클라우드 예약 작업 만들기·관리(대화로 설정) |
| `/batch <지시>` | 큰 변경을 5~30개 단위로 쪼개 병렬 처리(git 저장소 필요) |
| `/skills` · `/agents` · `/hooks` · `/mcp` | 스킬·서브에이전트·훅·외부 연결 확인 |

> 추천 순서: **`/insights` → `/plan` → `/code-review`**. 이 세 개만 일주일 써 봐도 체감이 큽니다.
