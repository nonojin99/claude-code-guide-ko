# 5. 믿고 맡기는 검증 루프

AI에게 일을 맡길수록 병목은 "만드는 일"에서 **"맞는지 확인하는 일"** 로 옮겨갑니다.
매번 사람이 다시 검증하지 않아도 되게 만드는 방법을 정리했습니다.

## 핵심 원칙: 지적은 검사로 바꾼다

AI를 고쳐줄 때마다 `CLAUDE.md` 에 한 줄씩 보태면 규칙 문서만 길어지고, 지켜질지는 여전히 확률입니다.
같은 지적을 두 번 했다면 **기계가 판정하는 검사**(스크립트, 린트, 테스트)로 바꾸고, 훅으로 그 검사를 통과해야만 넘어가게 하세요.

> 슬롭을 만드는 작업 루프를 자동화하면 슬롭만 늘어납니다. 자동화보다 루프의 품질이 먼저입니다.

## 단계

1. **정답 기준 정하기** — "좋은 결과"가 무엇인지 한 문장으로. 기준이 없으면 채점할 수 없습니다.
2. **확정된 규칙은 코드로** — 반드시 지켜야 하는 조건은 프롬프트가 아니라 필터·검사 스크립트가 처리하고, AI에게는 판단이 필요한 부분만 남깁니다.
3. **골든 케이스** — 정답이 확정된 과거 사례 20~30건을 모아 두고, 규칙이나 프롬프트를 바꿀 때마다 돌려서 맞히는 비율을 봅니다.
4. **예측 원장** — AI의 판단과 나중에 확인된 실제 결과를 같은 표에 쌓습니다. "믿어도 된다"가 느낌이 아니라 숫자가 됩니다.
5. **시각화** — 적중률·놓친 비율 추이를 그래프로. 동료를 설득하는 가장 빠른 방법입니다.
6. **단계적으로 맡기기** — 처음엔 추천만 하고 사람이 승인 → 적중률이 몇 주 연속 기준선을 넘은 부분만 자동화 → 떨어지면 다시 승인 단계로.

## 테스트 기법 고르기

| 기법 | 무엇을 | 추천도 |
|---|---|---|
| 예시 기반 테스트 | 정해진 입력에 정해진 출력 | 기본 |
| 속성 기반 테스트 | "어떤 입력이 와도 지켜야 할 성질"을 걸고 도구가 수천 개 입력으로 반례를 찾음. Python은 `hypothesis` | **가장 실용적** |
| TLA+ | 상태가 바뀌는 흐름(승인 단계, 동시 실행)의 설계 검증 | 운영 흐름이 복잡할 때만 |
| Lean | 수학적 성질의 증명 | 대부분 불필요 |

속성 예시(데이터 처리):
- 데이터를 추가해도 과거 기록은 줄어들지 않는다
- 입력 순서를 섞어도 결과가 같다
- 같은 데이터를 두 번 넣어도 결과가 같다
- 비율 값은 항상 0~1 사이다
